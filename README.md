# 商品相册 AI 开工包

版本：v1.0（文档第一版）。已完成文档走查，尚未完成独立复建验证。

**把这个仓库交给你的 AI，按你的需求搭建一套自己的商品相册。**

适合个体经营者、小商家，以及需要员工协助选品和报价的团队。也适合已有相册经验、准备启动下一个项目的人：复用经过实践的设计，少重复摸索。

这里提供具体的功能规格、数据与接口蓝图、实施步骤和避坑经验。你可以改变行业、页面风格、商品字段和技术栈，按需裁剪功能。AI 需要在你的开发环境中生成和验证应用；这个仓库本身不包含可直接启动的相册程序。

## 可以搭出怎样的相册

| 能力 | 用户可以怎样使用 | 选择方式 |
|---|---|---|
| 商品目录 | 搜索、按分类浏览、查看详情和图片、复制介绍、联系商家 | 基础闭环 |
| 商品管理 | 新建商品、维护图片、保存草稿、发布和下架 | 基础闭环 |
| 批量导入 | 从表格和图片目录整理商品，预览问题后再确认导入 | 可选 |
| 价格展示 | 可以公开零售价，也可以只展示商品、引导询价 | 可选 |
| 员工模式 | 登录后查授权价格、获取销售素材 | 可选 |
| 单品与多商品报价 | 选择商品、填写数量、生成可分享的报价结果 | 可选，依赖员工与价格规则 |
| 购买意向 | 客户整理感兴趣的商品，提交给商家跟进 | 可选 |
| 组合商品 | 按组成项与附加费用测算价格，修改后复核 | 可选，按实际业务定义 |

“轻量”体现在范围明确：参考方案以商品资料、展示、报价和咨询为主；数据库任务表即可承接初期图片处理。支付、库存扣减、物流、多商户等需求可以另加，但要单独设计状态、权限和验收，不能当成现有能力顺手打开。

## 和商城、其他商品相册有什么不同

本包适合这样的需求：**先把商品展示、选品、报价和咨询做好，同时希望字段、页面、权限和运行环境能按自己的业务决定。**

下面按使用方式区分，不代表所有产品都具备相同能力，也不是性能或价格排名。

| 选择方向 | 你获得什么 | 需要考虑什么 |
|---|---|---|
| 完整商城系统 | 围绕商品、下单、支付与履约组织的交易能力 | 如果首期只需展示和询价，先确认是否需要完整交易流程 |
| 现成商品相册服务 | 使用服务商已提供的商品展示与经营功能 | 核对所选服务的定制范围、数据导出、费用与平台规则 |
| 可运行的开源相册程序 | 已有代码，按其说明安装并在代码基础上修改 | 核对它的用途是否是商品经营，以及技术栈、许可和维护状态 |
| 本 AI 开工包 | 功能规格、架构、接口参考、实施顺序和验收依据，交给自己的 AI 建设 | 需要自行生成、验证、部署和维护应用，不能下载文档后直接营业 |

例如，Shopify 官方介绍包含商品、库存、支付和配送管理，也提供定制和扩展；现成商品相册也可能覆盖共享素材、客户选款下单。因此，本包的区别不能概括成“其他产品只能放图片”或“只有这里能定制”。参考：[Shopify 官方介绍](https://www.shopify.com/faq)、[微购科技官方介绍](https://www.wegobiz.cn/home/index.html)。产品能力以各自最新说明为准。

### 这套资料希望带来的优势

- **按需建设，保持范围轻量。** 从商品展示与管理开始，员工、报价、导入等模块按依赖选用；参考架构初期不要求 Redis 或消息队列。
- **把定制落到具体设计。** 不只替换名称和颜色；商品字段、价格规则、角色权限、联系方式及技术栈都可以调整，并有相应的验收入口。
- **复用已经整理的工程经验。** 图片来源与派生关系、草稿发布、导入异常、报价恢复和敏感字段权限，都有明确问题、设计建议和检查场景。
- **支持自己的环境与后续接手。** 要求新项目提供可重建说明、备份恢复和 AI 交接记录，便于以后迁移或继续开发；这些能力仍需在新项目实际实现和验证。

如果你愿意用 AI 建设自己的工具，这些资料可以作为起点。如果你需要马上开店，或者不想承担部署、备份和维护，现成服务可能更合适。本包开放获取，但 AI 使用、服务器、存储和维护仍可能产生费用；尚无独立复建数据证明它比现成方案更便宜或更快。

## 三步开始

1. **把本仓库放到 AI 能读取的位置。** 可以下载到本地，也可以提供仓库链接；若 AI 无法联网或访问文件，先把下面的入口和所需资料提供给它。
2. **告诉 AI 你的用途。** 可以填写[项目需求模板](templates/项目需求.md)，也可以直接描述，让 AI 帮你补齐。单人经营可参考[单人展示型](examples/单人展示型.md)，销售团队可参考[团队报价型](examples/团队报价型.md)。
3. **让 AI 从入口开始。** 复制下面这段话即可：

```text
请读取这个仓库的 START_HERE.md，按我的需求建设一个新的商品相册。
先帮我整理需求和首期功能，提出推荐方案并说明需要我决定的事项。
保留适用的设计经验，也允许我自定义功能、界面和技术栈。
在我指定的新项目目录中分阶段实施，每阶段给出可操作的结果和验证记录。
不要把参考文档已经存在，当成新应用已经实现或测试通过。
```

## 技术基础是什么

参考项目使用 **Vue 3 + TypeScript、NestJS、Prisma、PostgreSQL、Sharp**，以 **pnpm workspaces** 组织管理员网页、客户与员工共用网页、业务 API 和后台任务。图片区分原图、展示图、缩略图；权限由服务端控制。

沿用这套方案可以减少重新选型。你也可以替换框架或存储：让 AI 说明替换如何影响权限、数据关系、发布、图片任务和测试，再实施。[查看技术蓝图](docs/技术蓝图.md)
