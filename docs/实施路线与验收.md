# 实施路线与验收

这是给建设新应用的 AI 使用的工作顺序。按功能选择跳过不适用阶段，记录原因。每阶段都应有可操作的结果；完整应用的搭建时间依需求和开发环境而定。

## 阶段 0：确定要建什么

输入：使用者描述、需求模板、现有环境。

交付：新项目的 `PROJECT_BRIEF.md`、`IMPLEMENTATION_PLAN.md`；选中模块、角色可见字段、主要页面、数据对象、技术选择和阶段验收表。

通过条件：使用者能看懂第一版有什么、暂不做什么；AI 能将每项功能定位到实施任务。已有明确授权就继续，不重复问同一决定。

## 阶段 1：空项目可启动

建立目录、依赖、数据库连接与迁移、健康检查、管理员初始化、登录与退出。媒体目录独立持久化。提供实际可运行的安装、启动和停止命令。

通过条件：全新空数据库可建表，管理员能安全创建并登录，重启后账号仍在；未登录不能操作管理接口。不存在固定通用管理员密码，也不借用原项目数据库。

## 阶段 2：先做一条完整相册流程

管理员创建虚构商品、上传示意图片、生成派生图、保存草稿、发布；客户列表搜索、分类、详情、复制文案、联系商家。先做使用者选中的基础字段与一种联系方式。

通过条件：执行 C01–C06 及 C10；两端数据真实连通，错误和空状态可用，草稿修改不改变公开版本。

## 阶段 3：添加选择的业务模块

按依赖实现导入 → 价格与员工 → 报价；意向、组合商品和推荐设置按需求加入。关闭功能时服务端也要处理禁用状态，不能只移除按钮。

通过条件：所有选中模块对应 O01–O06 或新增测试，未选模块标记不适用。冲突、超时、重试、账号停用等路径按风险验证。

## 阶段 4：从别人的视角重新搭建

以新目录、空数据库和虚构素材，只使用新项目 README 重建环境。完成管理员初始化、导入或新建、派生图片、发布和选中的业务流程。检查备份恢复与更新方式。

通过条件：C07–C09 通过；说明书中的命令实际执行过，所需文件在交付包中。新环境不能依赖开发机的私有镜像、绝对路径或未写明的手工修改。

## 阶段 5：交接与可选发布

整理运行说明、必要配置、已选功能、已知限制、验收记录和恢复办法。在使用者授权的范围内发布；未授权公网发布则交付本地版本，明确停止位置。

通过条件：使用者完成自己提出的操作场景；另一位 AI 能按记录找到当前版本与下一步。实际设备尚未验证时如实保留待验项。

## 核心验收场景

| 编号 | 操作 | 预期结果 |
|---|---|---|
| C01 | 创建商品、上传两张示意图、保存草稿 | 管理端可预览；公开目录和详情均不可见 |
| C02 | 图片就绪后发布，再以未登录身份访问 | 列表与详情可见；只含允许公开的字段 |
| C03 | 修改已发布商品的草稿，明确清空图片或调整排序 | 发布前正式页不变；发布校验阻止不完整状态；成功发布后内容与图片一致 |
| C04 | 未登录及低权限身份访问管理、员工、原图入口 | 无权请求被拒绝；响应、错误信息和媒体下载不泄漏内部内容 |
| C05 | 连续打开两个商品、慢响应、返回列表、切后台再恢复 | 旧响应不覆盖新页面；列表位置符合设计；不会弹出不必要的重复状态 |
| C06 | 图片损坏、派生失败、断网、无商品、无搜索结果 | 明确反馈；可安全重试；失败商品不会被误标为完整发布 |
| C07 | 停止并重新启动服务 | 数据、图片、账号与所选业务记录保留 |
| C08 | 从空环境按 README 初始化 | 无开发机私有依赖；核心流程与前次一致 |
| C09 | 将备份恢复到独立新实例 | 商品与媒体关联、权限、登录和选中业务流程可用；原实例不被覆盖 |
| C10 | 配置联系入口，客户复制介绍、发起联系；再清空或关闭联系配置 | 复制内容与正式介绍一致，失败时可手动选择复制；入口与公开配置一致；缺失或关闭时不出现无效跳转，不暴露内部联系方式 |

## 可选功能验收场景

| 编号 | 适用模块 | 操作与判定 |
|---|---|---|
| O01 | 导入 | 重复编号、图片缺失、格式错误先进入异常列表；确认前不批量写正式数据；重复应用同一请求不产生重复商品；应用后图片进入对应商品图库，派生图 READY 后才能发布，客户能浏览；缺图或处理失败不能标记整条流程成功 |
| O02 | 价格 | 客户响应不含内部价或进价；手工指定价格不被公式覆盖；并发旧版本改价被拒绝；隐藏价格时无预算/排序旁路 |
| O03 | 员工 | 管理员创建员工后可登录；普通员工不能管理账号；停用、凭证重置、角色改变或退出后旧会话失效；保护最后一个有效管理员；旧响应不回填，切换账号后不显示上一位员工的数据 |
| O04 | 报价 | 保存草稿后重新登录可恢复，员工间不能读写对方草稿，旧版本保存被拒绝，删除草稿不改正式历史；服务端正式生成成功但客户端超时，按同一标识恢复，只有一份正式结果；过期、价格版本变化与恢复失败有清楚提示 |
| O05 | 购买意向 | 合法提交可供管理员列表、详情查看并跟进关闭；重复提交不重复建单；关闭入口后拒绝新提交，既有记录仍可管理；联系方式仅授权角色可读；按已定策略删除或匿名化后不可继续读取原联系方式 |
| O06 | 组合商品 | 草稿测算不修改正式配方或价格；组成项变更只触发约定的复核；首次发布相关数据原子生效 |

每个场景在实施记录中写出实际证据、环境和限制。权限与交易边界适合自动验证；手机保存图片、长按、软键盘与浏览体验需要对应设备验收。

## 新需求怎样进入

给新功能一个编号，补充角色、数据、状态、接口、失败路径和验收场景，并说明影响哪些现有用例。批准范围内继续实施，不把整个新项目拉回从头选型。
