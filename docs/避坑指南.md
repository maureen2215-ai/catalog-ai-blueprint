# 避坑指南

以下前五项来自参考项目中实际遇到并处理的问题；后两项是把这些经验用于新项目时的交付检查。它们是实现与验证线索，不代表新项目自动获得了修复。

## 1. 图片压缩后相同，业务来源仍可能不同

**发生过什么：** 不同原图生成相同内容的展示图，旧唯一约束让批量任务在服务切换前中断。

**设计办法：** 把文件内容去重与媒体业务身份分开。派生记录以来源原图、变体、转换版本识别；物理文件可复用，但图册关联不能被合并丢失。任务按来源可重试、可续跑。

**怎样验：** 用不同来源而派生结果相同的两份虚构输入，确认两条来源关系、封面与顺序均保留；中断后续跑不重建重复业务记录。核验按来源覆盖率，而不只看生成文件总数。

## 2. 商品来源变成两套编辑系统

**发生过什么：** 表格导入与后台新建逐步形成不同编辑入口和操作体验，基础维护重复。

**设计办法：** 分清创建来源、商品类型与浏览分类。统一列表、编辑外壳和操作语言；普通商品、组合商品保留真实不同的价格与配方事务。共享稳定部分，避免把所有情况塞进一个巨型表单。

**怎样验：** 导入与手工创建商品都能在同一列表检索、编辑、发布；改变分类不会伪造来源，也不会偷偷改变商品类型。

## 3. 草稿保存了，正式数据却被影响

**发生过什么：** 审查中发现清空图片后旧图回流，通用发布入口可绕过特定内容复核。

**设计办法：** 明确“未编辑该部分”与“主动清空”的不同状态；正式与草稿内容隔离；所有发布入口经过同一业务校验。首次发布原子提交必要资料、初始价格、配方及图片关系；后续正式改价走单独流程。

**怎样验：** 修改并清空草稿图片后刷新不会自动填回旧图；普通保存不会改变公开页；对所有发布入口运行同样的校验失败用例。

## 4. 慢网与会话切换让报价丢项或重复生成

**发生过什么：** 旧报价草稿恢复晚到，覆盖刚加入的商品；退出登录后旧查询继续触发创建；详情旧响应也可能写回已经离开的页面。

**设计办法：** 恢复完成前限制冲突编辑；请求带当前会话或页面代次，响应回来时核对；离页或退出后废弃旧结果。正式生成使用幂等标识，失败时区分明确不存在、服务不可用和结果未知。

**怎样验：** 人为延迟恢复请求、期间退出登录；旧请求不得创建新草稿。模拟服务端成功而客户端丢失响应，同一标识查回原报价，不新增第二份。详情连续切换时只接受当前商品的响应。

## 5. 搜索把型号当成拼音缩写

**发生过什么：** 字母与数字组成的型号被当成拼音首字母匹配，出现不相关商品。

**设计办法：** 分开编号/型号的精确或前缀匹配、名称文本匹配和可选拼音索引。优先级与规范化规则写清楚；特殊字符与大小写处理用测试固定。多语言项目应重新定义规则。

**怎样验：** 使用虚构的 `AB-12`、纯文字名称和纯字母缩写三个样例；型号结果不因拼音索引命中无关商品。用户实际需要的拼音搜索继续可用。

## 6. 看似隐藏了价格，接口仍能泄漏

这是新项目应保持的权限检查：客户端响应中直接不返回无权字段；媒体接口和报价响应也单独限制。关闭公开价格后，同时检查预算筛选、价格排序、分类计数等是否能推断价格。

**怎样验：** 以客户身份检查真实网络响应及可猜测的接口参数，而不只查看页面有没有显示数字。操作错误消息也不回显进价等内部数据。

## 7. 开发机可以跑，别人却缺配置和数据

新项目要从完整源码、锁定依赖、公开可取的基础镜像和配置模板重建；一次性内部发布脚本、固定镜像摘要、个人绝对路径和真实样本不能充当通用启动入口。

**怎样验：** 在空目录与空数据库中按新项目说明操作；演示数据全部虚构；首次管理员由使用者初始化。记录准确的构建来源和产物，避免发布目录里的代码与正在使用的代码不一致。

## 保留的限制：原图不能随意删

参考项目的原图记录仍承担封面、顺序和草稿等关系。新项目如果决定仅保存运营图，要先调整关系模型，再证明归档母图可取回并演练恢复。该项不能写成参考项目已经完成的优化。
