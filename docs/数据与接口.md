# 数据与接口蓝图

本页供 AI 设计新项目。关系与权限参考了实际实现，字段和接口契约经过简化，**不是从原服务导出的完整 API 文档，也不是当前可调用的服务**。可按需求改名或替换；新项目需要生成自己的 schema、迁移和接口契约，并让前后端与测试保持一致。

## 最小数据关系

| 对象 | 建议的最少字段 | 关系与约束 |
|---|---|---|
| User | id、username、passwordHash、role、active | username 唯一；管理员与可选员工；密码只存合适的哈希 |
| Session | id 或 tokenHash、userId、expiresAt、revokedAt | 属于用户；过期、撤销与停用均由服务端处理 |
| Product | id、name、description、categoryId、origin、kind、status、version | id 为稳定标识；来源、类型与分类互不替代；正式字段与草稿隔离 |
| Sku | id、productId、code、unit、specification | code 唯一；参考项目是一商品一 SKU，新项目有多规格时明确改为一对多 |
| ProductDraft | productId、baseVersion、draftVersion、fields、mediaEdited | fields 只允许预定义字段；发布需核对 baseVersion；清空图片与未修改图片区分 |
| MediaAsset | id、productId、sourceId、variant、transformVersion、storageKey、checksum、status | 派生记录引用来源；原图、展示图、缩略图区分；派生唯一身份不只靠文件哈希 |
| GalleryItem / DraftGalleryItem | productId 或 draftId、mediaId、position、isCover | 正式与草稿关系分开；顺序确定；单一封面；不可跨商品随意引用 |
| BackgroundJob | id、type、payload、status、attempts、leaseUntil、lastError | 业务幂等键防重复；worker 租约、重试与结果可追踪；payload 只放必要标识 |
| StorefrontSetting | name、contact、publicPriceVisible、enabledModules | 公开响应仅输出公开设置；秘密配置不放到公开对象 |

分类可按需求使用表或受约束字段。媒体关系可通过关联表或明确字段实现，不必为复制本页逐个创建表；但引用、排序、封面及草稿边界必须表达清楚。

### 可选业务对象

| 启用功能 | 增加的对象 | 关键规则 |
|---|---|---|
| 价格 | SkuPrice、PriceBatch、PriceChange | 金额用精确小数或明确最小单位；未知价格用 null，不伪造 0；手动价格和计算价格区分 |
| 导入 | ImportTask、ImportItem、MediaCandidate | 保留来源行、校验结果、匹配选择和应用状态；预览不直接写正式商品 |
| 报价 | QuoteDraft、Quote、QuoteLine | 正式结果保存商品、单位、数量、售价、规则版本等必要快照；原商品变化不改历史报价 |
| 购买意向 | PurchaseIntent、PurchaseIntentItem | 只收必要联系信息和商品快照；不携带内部价或进价；有去重和访问边界 |
| 组合商品 | CompositionVersion、CompositionItem | 引用来源 SKU、用量、费用与计算版本；草稿和正式版本独立 |

价格模块即使只有一种价格，也要明确金额精度、角色可见性和版本。是否单独建价格表可随需求决定；加入内部价、价格历史或批量调价时，应建立清晰的独立边界。

可选对象的建议最小字段：`QuoteDraft` 包含 id、ownerId、version、items、adjustments、priceVersion、updatedAt、expiresAt；读取和写入均校验归属，过期草稿不直接生成报价，价格和权限在正式生成时重新检查。`PurchaseIntent` 包含 id、requestId、status、contact、createdAt、version、closedAt、outcome；条目保存公开商品快照，内部跟进备注与公开提交结果分开。保留期限、删除或匿名化规则由需求决定，不能默认永久保留。

## 状态与事务

- 商品建议使用 `DRAFT → PUBLISHED → OFF_SHELF`，再按需支持 `ARCHIVED`。已发布商品编辑时创建独立草稿，不把正式商品直接改回不可见状态。
- 草稿发布必须检查版本。两个管理员基于同一旧版本编辑时，后来的提交应提示冲突，不能静默覆盖。
- 媒体使用 `PENDING / READY / FAILED`。真实文件写入并可读取后，才能标为 READY；数据库事务不能替代文件系统结果检查。
- 导入按“预检 → 审核 → 批准 → 应用 → 媒体处理”推进。具体枚举名自定，但不能把批准或任务入队当成全部导入成功。
- 初次发布需要的正式字段、图库关系、初始价格及组合信息在同一业务事务内生效。派生图片先在事务外完成，失败时不半发布。
- 后续正式价格变更单独校验与记录；普通内容保存或组合测算不隐式改价。

## 新项目建议的接口契约

以下 `/api/v1` 路径中，public/admin/sales 分区、草稿与发布、导入审核和批量报价的分离来自参考项目。表中的输入输出是建议的最小契约；带 `*` 的是为新项目补充的建议入口，不表示原服务采用这个精确路径。

| 方法与路径 | 身份 | 最小输入 → 输出 |
|---|---|---|
| POST `/auth/login` | 访客 | username、password → 用户的非敏感字段及安全会话 |
| POST `/auth/logout` * | 已登录 | 当前会话 → 撤销结果；重复退出安全 |
| GET `/public/products` | 客户 | q、category、cursor、limit → 公开商品列表、nextCursor |
| GET `/public/products/:sku` | 客户 | 商品编号 → 正式公开详情，未发布不返回 |
| GET `/public/media/:assetId` | 客户 | 派生图标识 → 图片内容；拒绝原图与不可见商品资源 |
| GET `/public/storefront` * | 客户 | 无 → 店铺名称、公开联系入口、允许公开的功能设置 |
| GET / POST `/admin/products` * | 管理员 | 查询条件 / 新建资料 → 管理列表 / 草稿标识和版本 |
| PUT `/admin/products/:sku/draft` | 管理员 | 允许的 fields、图库修改标记、expectedVersion → 草稿与新版本 |
| POST `/admin/products/:sku/media` * | 管理员 | 图片文件 → mediaId、处理状态；发布仍等待 READY |
| POST `/admin/products/:sku/publish` | 管理员 | 预期正式与草稿版本 → 发布结果与新版本 |
| POST `/admin/products/:sku/unpublish` * | 管理员 | expectedVersion → 下架结果；公开页不再返回 |
| GET / PUT `/admin/storefront` * | 管理员 | 设置读取 / 允许修改的设置 → 新设置和版本 |

以上路径省略统一前缀 `/api/v1`。管理员与媒体路由均需对象级权限检查；未知字段拒绝或明确忽略，不能把整个请求体直接交给数据库更新。

### 启用对应模块后再加

| 模块 | 参考入口 | 输入输出与失败边界 |
|---|---|---|
| 导入 | POST `/admin/imports/catalog-preview` | 表格与映射选择 → taskId、统计与逐行问题 |
| 导入 | POST `/admin/imports/tasks/:taskId/items/:itemId/review` | 行级选择及预期版本 → 审核结果 |
| 导入 | POST `/admin/imports/tasks/:taskId/approve` | 预期任务版本 → 批准状态；仍有阻塞项则拒绝 |
| 导入 | POST `/admin/imports/tasks/:taskId/apply-job` | 任务版本、幂等标识 → jobId；重复请求指向原任务 |
| 任务 | GET `/admin/jobs/:jobId` * | 无 → 阶段、成功/失败项与可重试状态 |
| 员工管理 | GET / POST `/admin/users` * | 分页查询 / username、角色与安全初始化方式 → 非敏感账号资料；仅管理员，不返回密码或哈希 |
| 员工管理 | PATCH `/admin/users/:id` * | active、role、expectedVersion → 更新结果；撤销旧会话，保护最后一个有效管理员 |
| 员工管理 | POST `/admin/users/:id/reset-credential` * | 新凭证或一次性重置方案 → 完成结果；撤销旧会话，秘密不进日志 |
| 员工 | GET `/sales/products` | 查询条件 → 员工允许字段，仍不含进价 |
| 报价草稿 | GET / POST `/sales/quote-drafts` * | 查询 / 初始清单 → 自己的草稿列表 / 新草稿和版本 |
| 报价草稿 | GET / PUT / DELETE `/sales/quote-drafts/:id` * | 读取 / 清单及 expectedVersion / expectedVersion → 自己的草稿 / 新版本 / 删除结果；所有动作校验归属，写入校验版本 |
| 报价 | POST `/sales/quotes/batch` | 商品与数量、允许的调整、价格版本、幂等标识 → 固化报价及可分享字段 |
| 报价 | GET `/sales/quotes/by-request/:requestId` * | 幂等标识 → 自己的既有结果；未知与暂时不可查须区分 |
| 意向 | POST `/public/purchase-intents` | 商品清单、必要联系方式、幂等标识 → 确认编号；禁用、非法输入与重复提交明确处理 |
| 意向管理 | GET `/admin/purchase-intents` * | 状态、分页 → 摘要列表，默认掩码联系信息 |
| 意向管理 | GET / PATCH `/admin/purchase-intents/:id` * | 读取 / status、outcome、内部备注、expectedVersion → 授权详情 / 新版本；允许待处理→跟进中→已关闭或待处理→已关闭，关闭需结果说明 |
| 意向管理 | DELETE `/admin/purchase-intents/:id` * | expectedVersion、已确认的清理方式 → 删除或匿名化结果；按项目保留策略执行 |

以上补充入口是新项目的推荐设计。员工管理采用版本检查时，User 增加 version 字段。报价生成若关联草稿，输入应包含 draftId、expectedDraftVersion；事务中验证归属与版本并记录正式结果关联，响应丢失后用同一请求标识恢复，不盲目创建新报价。草稿编辑不自动生成正式报价。对外分享默认只导出允许字段；如需公开链接，另行设计随机访问标识、有效期和撤销，不直接暴露内部查询接口。

价格批次等进一步选择的能力，由 AI 在编码前补齐输入、输出、权限、状态和失败契约，并列入实施计划。购买意向关闭入口时拒绝新提交；已有记录仍按管理员权限及保留策略处理。访客不能凭确认编号读取他人的联系方式；匿名提交去重使用不可猜测的请求标识，重复响应只返回确认编号。

## 响应边界示例

下面是虚构结构示例，不是原项目数据，也不要求新项目采用完全相同的字段名。

```json
{
  "sku": "DEMO-A01",
  "name": "示例收纳盒",
  "unit": "件",
  "description": "仅用于开发演示",
  "images": [{"id": "demo-display-01", "variant": "DISPLAY"}]
}
```

公开价格关闭时，不返回价格属性，也不返回能推断价格的区间、排序或计算字段。开启时可增加小数字符串形式的零售价。员工可以得到授权内部价；进价只存在于管理员允许的响应中。

公开商品结构不包含供应商、内部备注、会话、存储绝对路径或原图访问地址。图片标识由受控媒体入口解析，不能直接把存储目录暴露成公开静态目录。

## 通用实现约定

- 为输入定义类型与运行时校验：文本长度、枚举、数值范围、分页上限、文件大小和可解码格式。上传文件名与图库路径要约束在允许目录，防止路径穿越。
- 会话 cookie 的安全选项、CSRF 防护或替代认证方案按部署方式落实；登录限流、撤销与账号停用要可测。
- 版本冲突返回可识别的错误码；客户端重载或合并后再提交，避免自动用旧值覆盖。
- 幂等标识按操作者与动作隔离，同一标识携带不同内容应拒绝；不能仅凭商品编号把所有正常后续操作去重掉。
- 错误响应只保留使用者需要的信息。服务端日志脱敏，密码、令牌、内部价和联系方式不直接回显。
- 对公开列表、登录态数据分别定义缓存策略；退出登录和切换账号时清理私有缓存。图片使用与变换版本匹配的缓存标识。

完成契约后再写前后端调用，并以[实施路线与验收](实施路线与验收.md)的场景检查真实响应和状态变化。
